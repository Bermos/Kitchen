# Implementer memory

What previous implementers of bermos/kitchen learned the hard way. One line per
lesson, dated, under the heading it belongs to. Merge duplicates; do not drop.

## Test blind spots

- 2026-09-09: The controller-runtime 0.23 fake client **strips managedFields from every read** unless the builder is given `WithReturnManagedFields()`, so any test whose subject is field ownership reads an object with no managers on it and quietly finds nothing. With the option on it also validates every seeded entry the way the API server does — an entry needs both an apiVersion and a fieldsType or the builder panics — and it tracks ownership through writes properly.
- 2026-09-09: That same fake client attributes a write with no field owner to `unknown`, where a cluster names the operator's binary from its user agent, which is why `manager` is in `platformFieldManagers`. A field-ownership test therefore has to stamp the operator's own writes itself, through interceptor functions on Create, Update and both subresource writes; it also never sets `Subresource` on a status write, so the status carve-out cannot be exercised through it at all.
- 2026-09-09: A fake-client behaviour change **silently disarms every assertion that depends on it**, not only the ones that fail. The same 0.23 managedFields strip that panicked one fixture also made `TestObjectsCarryTheMaterializedManifests` vacuous — the manifest sanitiser could be deleted outright and the package stayed green — because the fixture's entries never reached the code. When a dependency bump changes what a test double returns, grep the whole repository for tests reading that thing back and prove each still bites (break the code under test, watch it fail, restore it); fixing the file that panicked is the easy half.
- 2026-09-15: `ui/` has **no component tests** — no @vue/test-utils, no jsdom — and no browser exists in this sandbox (no chromium, no playwright, no puppeteer), so a CSS layout change is provable only by reading. What substitutes: grep the *built* CSS (`ui/dist/assets/*.css`) for each new utility and the `@media` it landed in, and grep every view and component for what the change can break (`sticky`, `h-screen`, `100vh`, `h-full`, `fixed`) before claiming it is safe. Say plainly in the PR body which screens were reasoned about rather than looked at.
- 2026-09-15: `ui/src/lib/design.test.ts` can assert on any SFC's source — it parses every `views/*.vue` and `components/*.vue` with `@vue/compiler-sfc` and has `walk`/`classes`/`elementChildren`/`templateOf` at module scope — so a structural rule a component test would otherwise be needed for ("the shell's root declares a height", "there is exactly one `<main>`") is three lines there. Append a new `describe` at the **end** of the file: concurrent branches all add near `the page frame`. It may also import the dashboard's own modules (`SETTINGS_SECTIONS` from `lib/project`) and derive its subject from a screen rather than a hand-kept list — walking `ProjectSettingsView`'s `v-if="current.id === '…'"` chain gives every settings pane, and following a pane that has no children into `components/<Tag>.vue` gives its content, so a new pane is picked up without anybody remembering to list it (#599).
- 2026-09-15: An envtest case can drive `startFailure` end to end without a kubelet: create a plain Pod in the app namespace with `webLabels(map[string]string{labelEnvironment: env.Name})`, then `Status().Update` it with a container waiting under `CreateContainerConfigError`. The reconciler reads it as a refusal on the next pass and the Environment goes Degraded, which is the only cheap way to exercise the Degraded branch of `updateStatus`. Clean it up with `DeferCleanup` and `client.GracePeriodSeconds(0)` — a plain Delete leaves it with a deletionTimestamp forever (no kubelet), which `refusalOf` skips, so the leak is harmless but the object stays.
- 2026-09-09: Three test files in this repository turn on field ownership: `internal/api/api_test.go`'s harness and `internal/controller/accesssweep_test.go` both need `WithReturnManagedFields()` on the builder, and `internal/controller/platformvolumes_test.go` needs nothing because its `applyOwnerOf` cases are plain structs with no client at all. Anything new that asserts on managedFields through a fake client belongs on that list.

- 2026-09-15: **A justification borrowed from a neighbouring comment has to be checked against the code, not against the comment.** #598 argued reveal-on-click from "the project view polls every ten seconds", lifted from a stale comment in the pane it was editing; the pane's only mount site, `ProjectSettingsView`, says twice that nothing on it polls (#470 moved it off the overview) and `useAsync` has no interval — the 10s pollers are `usePoll` in `BuildsView` and `ProjectDeploysView`. A stale fact reused is a stale fact promoted, and the branch shipped three copies of it. Before a code comment or a PR body leans on a neighbour's claim about behaviour, grep for the mechanism (`usePoll(`, `intervalMs`) and fix the original while you are in there.
- 2026-09-15: An **evidence** claim needs the same conditional a read does. `s.recorded` returns true where an installation keeps no audit log — `spec.compliance.audit` off means `Record` resolves to a nil store and answers nil — so a feature gated on it still works and is simply not evidenced. That is the right behaviour (the route must not be a permanent 503), but "the read is recorded" written flat is then false for that installation: #598 had it unconditional in eight places including the `--values` flag help, which is what somebody reads at the moment they run it. Write "where the installation keeps an audit log" and point at `docs/api/audit.md`'s "When there is nothing to read".
- 2026-09-15: A role-based argument written about a person silently reaches every **credential** holding that role. `developer` is the ordinary grant for a CI key's machine account (builds and cancellations are `developer`), and #596 made personal keys role-scoped per project too — so "whoever may overwrite may read" handed every `developer` key in a CI secret a new quiet read. It is correctly not breaking and takes no `!`, but the PR body and `docs/AUTH.md` have to name the consequence: overwriting is loud, reading is not.
- 2026-09-15: A "the API never answers this" test is only as wide as the paths it walks, and #598's had walked two of four. Before adding or removing a gate on a serialised field, enumerate every path that serialises it — for a project's env vars that is `envVarViews` (one caller, `projectView`, reached by six routes), `diffEnv` in configdiff.go, the new values route, and `environmentObjects`, whose raw Deployment manifest has always carried every literal. `grep -rn "EnvVar\|ConfigSnapshot" internal/api/` is the whole enumeration in one command.
- 2026-09-15: A view built from a CRD field whose exclusivity the *API* enforces is not exclusive on the object: `envVarsFromRequest` refuses `value` beside `secretRef`, and a Project written with kubectl carries both happily. A gate that assumes "the literal must be empty because a reference is set" is no gate at all — drop the literal explicitly, and write the fixture the API refuses (PATCH the legal ones, then `Client.Update` the stray straight onto the stored object) so the case is actually exercised.
- 2026-09-09: A "no X here" test built on a shared fixture set is usually a second copy of the positive case — `TestAnEnvironmentWithNoDomainsExcludesNothing` sat on `fixtures()`, which carries a Domain, so the genuinely-empty path was untested. Strip the thing the case is about out of the fixtures (a `withoutDomains` filter) rather than trusting the base set to lack it.

- 2026-09-09: `internal/api`'s shared `fixtures()` already carries a Domain (`shop-com`, shop.example.com, on the test environment) with no conditions, so any behaviour keyed on a Domain's status applies to *every* request test in the package. It now carries `RouteProgrammed=True` — a working domain is the right default for a fixture used everywhere — and a case that wants a half-up domain adds its own.

- 2026-09-07: The controller-runtime fake client admits objects into namespaces that do not exist. A first-provision ordering bug (a Certificate created before `ensureNamespace`) passed every unit test and failed only on kind. Pin ordering with a fake-client `interceptor` recording Create calls, and prefer a kind e2e case for anything that creates objects into a namespace it also creates.
- 2026-09-07: The CNB lifecycle (0.21.x) builds a buildpack's environment from an include list and **drops every other container variable**; `BP_*` and `NODE_OPTIONS` reach a buildpack only as files under the platform directory (`-platform`, `detector` and `builder` only). An assertion on a pod's container env proved nothing for months. The operator now writes a ConfigMap per buildpacks Job mounted at `/kitchen/platform/env`; assert on that, not on `env`.
- 2026-09-07: Moving an e2e case onto the branch that was never covered silently drops the branch it used to cover. #537 pointed the buildpacks case at a registry issuing a narrower credential and left `Read == Push` asserted nowhere; the fix was to state it on another case that still has it. When a case changes which side of a fallback it exercises, find the case that keeps the other side and assert it there.
- 2026-09-07: A fallback in the code under test can make a whole e2e case vacuous. `credentialsWithRead` falls back to `Read == Push` when there is no `<secret>-read` Secret, so every buildpacks credential assertion in CI held for a pod whose every container could push, and #534 shipped. Before asserting "this container holds the narrow thing", assert the two things are actually different (`scoped()`, two Secret names) — in the unit test and in the workflow.
- 2026-09-07: `registry:2`'s htpasswd auth is all-or-nothing — every account it admits can also push — so a read-only registry account cannot be made with it. nginx in front of the same storage can: `auth_basic` over two accounts plus `limit_except GET HEAD { auth_basic_user_file <writers only>; }`, with `client_max_body_size 0` and `proxy_request_buffering off` so blobs stream. Proven locally against a real registry with go-containerregistry, the library the CNB lifecycle uses.
- 2026-09-07: A kind e2e job with a component disabled (`--set cert-manager.enabled=false`) turns every path that needs it into dead code there; its green runs said nothing about that path. Check what the job disables before trusting its coverage.
- 2026-09-06: `Seal` in `internal/audit` stamps `time.Now()` when the timestamp is zero, so a "deterministic encoding" test that did not pin the instant flaked at millisecond boundaries. Pin timestamps in any test that seals, hashes or fingerprints.
- 2026-09-07: `kubectl get resourceclaim` resolves to Kubernetes 1.34's built-in `resource.k8s.io` ResourceClaim, not Kitchen's CRD. Always write `resourceclaims.kitchen.bermos.dev` in workflows and docs; a loop that swallowed the error with `|| true` hid this for the whole of a fifteen-minute wait.
- 2026-09-07: `cd ui && npm test` does **not** typecheck — vitest transpiles without checking. A required field added to an interface in `ui/src/lib/api.ts` breaks `npm run typecheck` (vue-tsc) alone, and CI's "Build, typecheck and unit tests" is where you find out. Run `npm run typecheck` beside `npm test` whenever an exported type changes.
- 2026-09-07: An envtest that builds an `Environment` struct by hand and passes it to a helper leaves `spec.type` empty, which now means "no class" rather than "production". Anything keyed on `env.Spec.Type` needs the field set in the fixture, not just the name.
- 2026-09-07: A claim's binding reaches a workload by **two** paths, and a change to one proves nothing about the other: the platform's own variables (`serviceBindingEnv`) and a `fromResourceClaim` entry the project wrote, resolved separately in `resolveEnv`'s `case v.FromResourceClaim != nil` arm. That arm reads `claim.Status.SecretName` and applies the *preview mode*, so a per-class or per-environment binding rule has to be repeated there or a preview silently gets production's address. Test both paths.
- 2026-09-07: `resolveEnv` returning `requeue=true` for an unbound claim makes the environment `notReady` and it never applies its Deployment. Any claim whose binding depends on *another team's* declaration must not go down that path — leave the variable out and say so on `ClaimsBound`.
- 2026-09-07: A condition reason written as a bare string falls to `severityError` in the dashboard — `conditionSeverities` (internal/api/conditions.go) is keyed on the operator's *exported* `Reason…` constants, and `TestEveryExportedReasonIsClassified` only sees exported ones. A new benign reason is three edits: export it, classify it, and check the screen is not now red for being polite.
- 2026-09-07: The API test harness's fake client gives a status subresource only to the kinds listed in `WithStatusSubresource` (internal/api/api_test.go). A handler calling `Status().Update` on any other kind gets a bare `<kind> "<name>" not found` that reads exactly like a missing object — the fix is to add the kind to that list, not to hunt the read.
- 2026-09-07: Turning a ConfigMap *directory* mount into `subPath` file mounts makes any `checksum/` annotation over the raw values wrong: the kubelet re-projects a directory into a running container but never a subPath, and chart values go through `tpl`, so hash the rendered ConfigMap (`include (print $.Template.BasePath "/<dir>/configmap.yaml") . | sha256sum`) or the change never reaches the process.
- 2026-09-07: A StatefulSet whose pod 0 cannot start cannot be fixed by `helm upgrade` — OrderedReady waits for pod 0 Ready *before* applying the new template, so the upgrade hangs. Any fix to a pod-template bug that already bricked installations needs an `### Upgrading …` section in `charts/kitchen/README.md` naming the one `kubectl delete pod` step, and a line in the self-update section's "cannot rescue" list.
- 2026-09-07: A `volumeMount` is only ever exercised by a kubelet, so no `helm template` check can catch one that stops the pod starting — a ConfigMap mounted as a *directory* over a path the image also populates crashes on any subPath mount into it and hides the image's files otherwise (#529, `/etc/clickhouse-server/config.d`). Assert the shape with a render check *and* set the value on the kind leg of `Chart install`, where `helm install --wait` is the only thing that proves a pod starts.
- 2026-09-07: A ClickHouse column added to a table's `CREATE` reaches a fresh install and nowhere else — `ensureAddedColumns` (`signalTransitionColumnsAdded` in schema.go) is the upgrade path, and the integration suite recreates tables so it never exercises it. Test it by `ALTER TABLE … DROP COLUMN IF EXISTS` then re-ensuring; a column named in a read and missing from the table is a query that reads perfectly and fails.

- 2026-09-08: `json:"x,omitempty"` on a `time.Time` never omits anything — a struct is not empty — so an absent instant serves `0001-01-01T00:00:00Z` and contradicts whatever the docs say about the field. Use `omitzero` (Go 1.24+), and assert on the raw response body, since a decoded struct cannot tell the two apart.
- 2026-09-08: Overlaying a refreshed sentence onto a stored row means overlaying what the sentence is *about*: `platform.correlated` recomputes `confidence`, `projects` and `correlates` every round, and refreshing the title alone left "4 projects failing together" over a list of two. Enumerate the descriptive fields that travel with the words, and keep the ones that feed the tier or the clock.
- 2026-09-08: A durable row written once at `StateOpen` is a *record of a moment*, and any screen over it shows the value the condition had when it fired — `internal/api/alerts.go` showed a volume at 85% for ten hours. The refreshed answer already exists in the detection loop's in-memory episodes (`signals.Tracker`); overlay it at read time and date it, never rewrite the row. Check every reader of `OpenSignalTransitions` when you do: `/platform/signals` reads the same rows and was left stale (#547).
- 2026-09-07: A ratio whose numerator and denominator come from different sources passes every test that sets both consistently — `store.disk` divided the `kitchen` database's parts by the PVC's nominal capacity and read 8.4% on a volume 89% full, with green tests either side of the threshold. Assert the *mixed* case (small numerator, full disk) or the bug is invisible (#531).
- 2026-09-08: ClickHouse renames a system log table the first time that log is **next written** after its definition changes, not at server startup — `text_log`/`trace_log` within seconds, `query_log` at the first query, `error_log` possibly hours. Any "clean up what the rename orphaned" step must be a sweep on every reconcile; a one-shot recorded in status collects the loud tables and leaves the quiet ones forever.
- 2026-09-08: A CI assertion of the form "no rows at level X" over a ClickHouse system table passes vacuously against an empty table. Select `count()` alongside the filtered count and require both.
- 2026-09-08: envtest runs **no garbage collector and no storage-protection controller**, so `--cascade=orphan` leaves the object with its `orphan` finalizer forever and every PVC keeps `pvc-protection`. A spec that deletes either and a next spec that recreates it under the same name fails with a 409 nobody expects — strip finalizers in `AfterEach` and wait for the object to go, or drive the delete/recreate path over two reconciles as the production code does.
- 2026-09-08: The API server refuses a size change to an **unbound** PVC — "spec is immutable after creation except resources.requests … for bound claims" — so any expansion path needs the claim Bound, in the fixture and in the code's own precondition. A Pending fixture makes the whole feature look broken for the wrong reason.
- 2026-09-08: Before writing "none of these has a TTL out of the box", read the image's own config: `docker run --rm --entrypoint sh <image> -c 'grep -n <ttl> /etc/clickhouse-server/config.xml'`. The pinned ClickHouse already bounds `query_log` and `processors_profile_log` at 30 days and `asynchronous_insert_log` at 3 — shipping the issue's suggested 7 for the last one would have been the chart *loosening* an upstream bound.
- 2026-09-08: A controller method called from one place and asserted nowhere is invisible to the whole suite. Prove the wiring by commenting the call out and watching the new test fail — and drive the test through the reconcile function, not the helper, or the mutation still passes.
- 2026-09-08: A helper that nils `ManagedFields` on a copy kills every later read of the *field manager* off it — `replacementFor` nil-ed it and `applyOwnerOf` then always answered "", so the whole server-side-apply-under-the-original-owner branch was dead code that every test passed. Assert the ownership on the recreated object (`applyOwnerOf(restored)`), not just that the object came back.
- 2026-09-08: A phase judged on `spec.resources.requests` reports a volume finished the moment the *request* moved; the driver's half is `status.capacity`, and a claim in `ControllerResizeFailed` has the request and not the space. Judge "done" on capacity, and carry the PVC's own condition message rather than composing one.
- 2026-09-08: A reconcile that writes status once at the end writes it with the resourceVersion the pass started with, so every value on it must be *recomputable next pass*. A record of an irreversible act (the system-log DROP, #562) is not: persist it where it happens with `Status().Patch(ctx, obj, client.MergeFrom(before))`, which carries no precondition — and the patch response refreshes the object, so the end-of-reconcile Update is not made stale by your own write.
- 2026-09-08: The controller-runtime fake client *does* enforce resourceVersion on `Status().Update` (given `WithStatusSubresource`), so a lost-update defect is reproducible at unit speed with no envtest: put the object in the client, have the fake HTTP store run a hook that bumps an annotation through a second read, then assert on the stored object rather than the one in hand.
- 2026-09-09: A hostname added to one of the *platform's own* HTTPRoutes is read by more than the gateway: `flows.PublishedHosts` treats every route's hostnames as "the platform published this name", and `edge.unrouted-hosts` subtracts that set — so scoping the port-80 redirect to `*.<baseDomain>` (#573) silently covered every abandoned generated URL and muted the signal. Enumerate the readers of `spec.hostnames` (attribution in `hostsFromRoutes`, publication in `PublishedHosts`) before putting a name on a platform route.
- 2026-09-09: An absence assertion passes against the code it is supposed to fail on: `Expect(list).NotTo(ContainElement(x))` holds for the `nil` the reverted code writes, so the one assertion naming the issue did no work. State the whole expected list (`To(Equal([]string{…}))`) whenever "the new thing is not here" is the point — and prove it by reverting the fix and watching it go red.
- 2026-09-09: A kind step that reads back `.spec` of an object the operator just wrote asserts what the envtest already asserts, twelve minutes and one cluster later. What a cluster leg is *for* is the implementation's side of it — on the Cilium leg the shared Gateway is programmed and publishes an address (`hack/install-cilium.sh` installs LB IPAM) even though its HTTPS listener names a wildcard certificate that is never issued, so a `kubectl run` probe pod curling `status.addresses[0].value` with `-H 'Host: …'` is available; the kindnet leg runs no Gateway controller at all.
- 2026-09-08: A parameter named `client` (e.g. `client *clickhouse.Client`) shadows `sigs.k8s.io/controller-runtime/pkg/client` for the whole function — `client.MergeFrom` will not compile until it is renamed. Check for the shadow before reaching for a controller-runtime helper inside such a function.
- 2026-09-15: The Cilium leg's shared Gateway has **no usable HTTPS listener** — the wildcard Certificate is ACME DNS-01 against a Cloudflare token that does not exist — so anything that must be proved over HTTPS there fabricates one: an openssl CA plus a leaf for `*.<baseDomain>` written into `kitchen-wildcard-tls`, the Secret the listener already names, then wait on the `https` listener's `Programmed` condition. cert-manager neither overwrites nor deletes a Secret it never issued into, and the probe trusts that CA alone.

## Tooling and environment

- 2026-09-09: controller-runtime 0.21 stopped setting a client-side rate limit on the config `GetConfig`/`GetConfigOrDie` hand back (upstream sets `QPS = -1` and relies on API priority and fairness), and it documents setting the fields back as the supported way to keep one. Kitchen restores QPS 20 / burst 30 in `cmd/main.go` and in `cmd/gate/main.go`'s `startDirectory` — the two long-lived binaries — so an upgrade does not change how an installation behaves. `cmd/backup` and `cmd/restore` are short-lived and take the new default; `cmd/qualitygate`, `cmd/rescan` and `cmd/volumeinit` build no Kubernetes client at all.
- 2026-09-09: A `rest.Config`'s QPS and burst are a token bucket **per REST client**, and controller-runtime builds one per GVK (`clientRestResources.newResource` → `apiutil.RESTClientForGVK`), with further buckets for the uncached reader and any clientset built beside the manager. "Bounded at 20 queries a second" describes one kind, never the process — say so when writing it down.
- 2026-09-09: Prose duplicated by repeated rebases through one paragraph is invisible to `sort | uniq -c`, because the copies have drifted — an 8-gram shingle count over the file with fenced code blocks stripped (`re.sub(r'```.*?```','',t,flags=re.S)`, then `Counter(' '.join(words[i:i+8]))`) finds every interleaved copy in a doc in seconds, and finding *none* elsewhere is what lets you say the siblings were looked for. Run it over the whole file before fixing the lines the issue handed you.
- 2026-09-15: Tailwind 4's `lg` compiles to `@media(min-width:64rem)`, which is the same 1024px `AppShell.vue`'s own `matchMedia("(min-width: 1024px)")` uses — the two are already a pair, so a `lg:`-gated layout change and the drawer's JS agree without a new constant. Confirm a new utility actually got emitted by grepping the built CSS; `npm run build` then a `re.finditer` over `dist/assets/*.css` answers both questions in seconds.
- 2026-09-09: The Kubernetes stack moves as one: controller-runtime 0.20 pairs with 1.32, 0.21 with 1.33, 0.22 with 1.34, 0.23 with 1.35, and controller-tools v0.20.1 is the generator that pairs with 1.35. `ENVTEST_VERSION` and `ENVTEST_K8S_VERSION` are derived from the modules in the Makefile, so only `CONTROLLER_TOOLS_VERSION` is edited by hand; regenerating then rewrites the `controller-gen.kubebuilder.io/version` annotation in eighteen files and nothing else.
- 2026-09-09: `go build ./...` and `go vet ./...` clean say nothing about a controller-runtime bump. The whole cost of 0.20 to 0.23 here was runtime behaviour in the fake client, found only by running `make test`; measure a dependency bump with the suite, not with the compiler.
- 2026-09-09: The main checkout may have **no** `ui/node_modules` at all (it did not on the #574 run), so the "symlink rather than reinstall" shortcut silently leaves a dangling link and `npm run build` fails with `vite: not found`. Check `ls /home/user/Kitchen/ui/node_modules` before symlinking; `npm ci` in the worktree takes about a minute and is the fallback. Remove the `bin` symlink before committing — it shows up as untracked.
- 2026-09-15: **Never `git checkout <path>` to undo a scratch edit on uncommitted work** — the file is tracked, the changes are not staged, and it reverts to HEAD, losing an hour of edits in silence. Commit early and often on the branch instead, and undo a scratch edit with the inverse edit. (Lost all of `internal/cli/cmd_env.go` this way; re-applying from the patch script in scrollback was the only recovery.)
- 2026-09-15: Keep every multi-hunk edit in a heredoc'd python script with `assert old in s` per hunk rather than in a sequence of `sed -i`s: it is idempotent to re-run, it fails loudly on a hunk that no longer matches, and it is the file you re-run verbatim when something eats your work. `sed -i` with `\n` in the replacement writes the literal two characters into a Go string, which compiles and reads wrong.
- 2026-09-06: Run `make` with `LOCALBIN=<main checkout>/bin` from a worktree, or it downloads envtest, controller-gen and golangci-lint again. Symlink `ui/node_modules` rather than `npm ci`.
- 2026-09-06: Auth service tests need a local Postgres (`pg_ctlcluster 16 main start`; `KITCHEN_AUTH_TEST_DATABASE_URL=postgres://postgres:postgres@127.0.0.1:5432/kitchen_auth_test`). The ClickHouse integration suite needs Docker (`dockerd &`) and `KITCHEN_CLICKHOUSE_URL` against the pinned `clickhouse/clickhouse-server` image; say in the PR body if you could not run it.
- 2026-09-06: The Go build cache fills the disk over a long session; `find ~/.cache/go-build -type f -amin +120 -delete` and `docker system prune -af --volumes` recover it.
- 2026-09-07: `dockerd &` plus a `docker network`, a `registry:2` and a scratch `_test.go` using the repo's own `go-containerregistry` is a two-minute way to prove a registry-side workflow change before pushing it — push, pull and a refused push, each with a different account. Delete the scratch test before committing; a stray `zz*_test.go` is easy to leave behind.
- 2026-09-07: `make lint` catches what `make test` does not: goconst on a string repeated across test assertions (`"dir"`, a release name), gocyclo at 30 on `Reconcile` (extract a helper), unparam on an always-nil return, staticcheck SA4000 on a "is this stable" test that compares one expression to itself (assert the exact expected string instead).
- 2026-09-07: `kind` does **not** come up in this sandbox even with `dockerd &` running — the control plane's sandboxes die on `runc create ... can't get final child's PID from pipe: EOF` (nested runc). Plain `docker run` works, so an image-layer or bind-mount question can still be answered directly (`docker run -v dir:/path` vs `-v file:/path/file` proved #529's hidden `config.d`); anything needing a kubelet is CI's kind jobs, and say so in the PR body.
- 2026-09-07: `internal/attestation/store.go` is the template for any new OCI-referrer mechanism (#498's release artifacts copied it): attach to a `name.Digest`, read the subject descriptor with `remote.Head` rather than assembling it, push the manifest under a `sha256-<hex>.<suffix>` tag as well so a registry without the referrers API still answers, and be idempotent by layer digest. Do not speak the registry API directly.
- 2026-09-07: `internal/api/requests.go` already exists and is about HTTP *request telemetry*. Check `git show HEAD:<path> | wc -l` before creating a file in a package this big — Write overwrites silently, and the only symptom is a wall of "undefined" errors in unrelated files.
- 2026-09-07: `cd ui && npm run typecheck` fails wholesale (`Cannot find name 'useToast'` in twenty files) until `npm run build` has generated the auto-import declarations. Always run `npm run build` first, then typecheck; CI does.
- 2026-09-15: `make test LOCALBIN=<main>/bin` puts envtest under `<main>/bin/k8s/<ver>-linux-amd64`; exporting `KUBEBUILDER_ASSETS` to it lets you re-run one ginkgo suite in ~20s (`go test ./internal/controller/ -count=1 -args -ginkgo.focus="<Describe text>"`) instead of the 10-minute full run. Add `-v` and grep for `Ran N of` to prove a newly added spec was actually selected rather than silently skipped.
- 2026-09-15: goconst in this repo's config does **not** fire on a string literal repeated fourteen times across the package's test files (`"CreateContainerConfigError"` is), so the rule is narrower than "three occurrences anywhere". Do not spend a round defensively hoisting consts before running `make lint`; run it and fix what it names.

## Design rules that bit
- 2026-09-15: **A two-part header row squeezes its button below its own label only when the row does not `flex-wrap`.** Flex line-breaking uses each item's *max-content* hypothetical size and happens **before** any shrinking, so on a wrapping row two items either both fit (nobody shrinks) or the second takes its own line; on a non-wrapping one both give way in proportion and `Add a secret` breaks into `+ Add a` / `secret` (#599). Hence the two answers and no third: `shrink-0` on the controls side (`PageSection`), or the row wrapping **and the controls' own row wrapping too** (`PageHeader`) — wrap on the row alone still squeezes three buttons alone on a phone-width line, and `shrink-0` on a container kills any `flex-wrap` inside it, because the container then keeps its max-content width. And **a source-reading rule is an allowlist of *spellings*, not of files**: keyed on `flex justify-between` **plus** `items-start|items-center` it caught every new header in those two spellings and missed three live ones aligned `items-baseline`, `items-end` and not at all — one of them the reported defect itself, on a screen absent from my own hand-check list. Name the least of a shape that identifies it, then delete the extra clause and re-run *before* fixing anything: what fails is the true blast radius, and a `:class` sweep proves no fourth row hides the shape in a binding.
- 2026-09-15: **`PageSection` is not a drop-in for the hand-rolled header it replaces**: its description is a single `<p>` wrapping the slot, and six of the settings panels carry two description paragraphs, so adopting it is a markup restructure — not a rename. With no browser in the sandbox that is a change you cannot look at; giving the hand-rolled rows `PageSection`'s *behaviour* (one class) and enforcing it in `design.test.ts` is the reviewable half. Say which you took and why in the PR body.
- 2026-09-15: When a rule gains a distinction (#599 D2: a form keeps `max-w-3xl`, a pane whose content is a table takes the column), make the *data* declare which side it is on — a required field on `SettingsSection` means TypeScript refuses the next pane that does not say — and assert only the direction that is true: "takes the column ⇒ draws a list" bites, its converse does not. **Then check the tie-break against every row before writing it down**: "the part somebody fills in decides" was false of Members (a table *and* a real add form, and one of D2's own four) and had no answer for Notifications (cards each wrapping a `<table>`), so the sentence over-promised on three of fifteen panes. What a pane is *about* is the tie-break that matches the tree, and it is the scope rule's own reasoning, so it costs the guide no new vocabulary; name the one real exception where its `width` is declared.
- 2026-09-15 (corrected after review): An issue's "starting points" are to be disproved in words, not quietly skipped — but **a disproof holds only for the surface it was run against, and saying so is the whole of it**. #597's de-duplication lead: the pull request comment is *upserted*, so a preview that dipped through Degraded reads `Ready` at rest, and the reporter saw `Failed`. True, and it does **not** touch the statistic the issue was built from, which came from GitHub deployment *records* — a recovery landing after a newer push is posted against the newer record and the older one keeps `failure` for ever. State the disproof's scope in the same sentence as the disproof; back it with a regression test where you can; and never write "categorically" about a skip condition without checking its clock (`imagePullGrace` is ten minutes, so a pod becomes a refusal with no deploy in between).
- 2026-09-15: **When a published payload stops being a pure function of its de-duplication key, the key has to grow with it.** `reportDeployStatus` keyed on `{revision, state, url}`, which fully determined the description while that was `fmt.Sprintf("%s could not be deployed", name)`; the moment the description carried a *reason*, the first cause froze on the pull request for ever while the dashboard, reading the conditions live, moved on. Growing it costs the other half, though, and both questions are one question: a key that is the *text* re-posts whenever the text moves and the fault does not — the kubelet alternates `ErrImagePull` and `ImagePullBackOff` for one unpullable image, both refusals past the grace, so the forge and the public pull request comment are rewritten about a dozen times an hour until somebody fixes the image (#614). Before adding an input to anything posted once, find the suppression check and ask both what it now fails to notice and what it will now repeat.
- 2026-09-15: **A test that asserts two things agree, over a fixture that wrote both of them, is an assertion about the fixture.** #605's criterion-5 test compared the specific condition's message with `Ready`'s on a helper that set both to one string: it passed against the fix reverted *and* against the writer mutated to disagree — bites in neither direction. Drive such a property through the production writer (here the reconcile, not a struct literal), and prove it by breaking the writer. The same trap swallows a negative assertion whose fixture cannot produce the thing: `NotTo(ContainSubstring("Change it in"))` proved nothing on a release that declares no security posture, because the clause only exists when one is declared.
- 2026-09-15: Two conditions carrying the *same* sentence is not duplication here, it is the mechanism that keeps the dashboard and the git report in step: `updateStatus` and `awaitingDeployTasks` each write their message onto the specific condition **and** onto `Ready`, and anything that needs "why is this object unwell" in one string reads `Ready` and gets the words already on the screen; writing a third wording is the drift. **Do not claim `statusDetail` is the screen's reader without checking which screen**: `ui/src/lib/status.ts:103` returns the first unhealthy condition *in array order*, never `Ready`, and `internal/api/conditions.go:174` defaults an unclassified `False` to `error` — so `ScaleToZero=False/AlwaysOn`, written ahead of `WorkloadAvailable`, wins it on a production environment (#612). For a preview nothing uses `statusDetail` at all (`attention.ts` is production-only); the reader is `EnvironmentView.vue`'s refusal callout plus `ConditionsTable`.
- 2026-09-15: A status field the operator publishes to a *forge* has no policy row, no docs/api page and no CLI command — the surface belongs to GitHub, not to the API — so the "every route needs five things" chain does not apply and the PR body has to say so explicitly, or a reviewer reads the missing rows as an unfinished chain.
- 2026-09-15: A provider truncates what it is handed (GitHub cuts a status description at 140 chars, `githubDescriptionLimit`), so a composed sentence puts the *fact* first and the *reason* second and the long surface — the pull request comment — carries it whole. `previewBlock`'s Headline/Reason split is the existing precedent; follow it rather than inventing a second shape.
- 2026-09-15: Giving vue-router a `scrollBehavior` **at all** switches `history.scrollRestoration` to `manual` (vue-router.mjs, `createRouter`) — **globally, however `lg:`-gated the CSS half of the change is.** So a shell that only bounds its height at `lg` still changes every phone: a cross-path navigation now jumps to the top and back/forward is your manual restore rather than the browser's. Gating the behaviour on `matchMedia` is worse, not better (restoration is already manual and would go unhandled), so name the phone cost in the PR body and the design guide instead of writing "below `lg` nothing changes". Its `savedPosition` is also computed from `window.scrollY`, which is zero once an element scrolls, so remember the pair (element and window) per `fullPath` in a `beforeEach` — by the time `scrollBehavior` runs, one `nextTick` after the route is confirmed, the screen you left is gone.
- 2026-09-15: A screen that scrolls to a place inside itself (`EnvironmentView`'s `?section=`) does not race a router-level scroll reset: the reset runs one `nextTick` after the navigation and the screen's own `scrollIntoView` waits on its `useAsync` data, a network round trip later. `scrollIntoView` also scrolls whichever ancestor is scrollable, so moving the scroller needs no change there.
- 2026-09-15: **Restoring a scroll position in `scrollBehavior` is one assignment at the wrong instant.** It runs one `nextTick` after the route is confirmed, when every view's `useAsync` is still `shallowRef(null)` with no cache, so the scrollport holds a loading state and `scrollTop` clamps to about zero — a back or a forward lands at the top on every data-driven screen. (No regression: the browser's `auto` restoration clamped identically.) A real restore has to re-aim until the content stops growing, with three guards — abandon on the reader's own `wheel`/`touchstart`/`keydown`, cancel on a new navigation, and a hard deadline — which is interactive behaviour, so do not ship it without a browser to watch it.
- 2026-09-15: Moving a page's scroll out of the document takes **keyboard scrolling** with it: space, page down and the arrows follow the scroll chain of whatever has focus, and a page load and every navigation leave that on `<body>`, which is no longer a scrollport. Chrome's keyboard-focusable-scroller promotion does not rescue it — that is for scrollers with *no focusable children*. The fix is `tabindex="-1"` on the landmark plus focusing it, and three details make it safe: only on a **path** change (a query change would steal focus from the control that changed it), `focus({preventScroll: true})`, and from `afterEach` — which runs before Vue's flush, so a view's own autofocus still wins.
