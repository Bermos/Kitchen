# Implementer memory

What previous implementers of bermos/kitchen learned the hard way. One line per
lesson, dated, under the heading it belongs to. Merge duplicates; do not drop.

## Test blind spots

- 2026-09-09: `internal/api`'s shared `fixtures()` already carries a Domain (`shop-com`, shop.example.com, on the test environment) with no conditions, so any behaviour keyed on a Domain's status applies to *every* request test in the package. It now carries `RouteProgrammed=True` — a working domain is the right default for a fixture used everywhere — and a case that wants a half-up domain adds its own.

- 2026-09-07: The controller-runtime fake client admits objects into namespaces that do not exist. A first-provision ordering bug (a Certificate created before `ensureNamespace`) passed every unit test and failed only on kind. Pin ordering with a fake-client `interceptor` recording Create calls, and prefer a kind e2e case for anything that creates objects into a namespace it also creates.
- 2026-09-07: The CNB lifecycle (0.21.x) builds a buildpack's environment from an include list and **drops every other container variable**; `BP_*` and `NODE_OPTIONS` reach a buildpack only as files under the platform directory (`-platform`, `detector` and `builder` only). An assertion on a pod's container env proved nothing for months. The operator now writes a ConfigMap per buildpacks Job mounted at `/kitchen/platform/env`; assert on that, not on `env`.
- 2026-09-07: Moving an e2e case onto the branch that was never covered silently drops the branch it used to cover. #537 pointed the buildpacks case at a registry issuing a narrower credential and left `Read == Push` asserted nowhere; the fix was to state it on another case that still has it. When a case changes which side of a fallback it exercises, find the case that keeps the other side and assert it there.
- 2026-09-07: A fallback in the code under test can make a whole e2e case vacuous. `credentialsWithRead` falls back to `Read == Push` when there is no `<secret>-read` Secret, so every buildpacks credential assertion in CI held for a pod whose every container could push, and #534 shipped. Before asserting "this container holds the narrow thing", assert the two things are actually different (`scoped()`, two Secret names) — in the unit test and in the workflow.
- 2026-09-07: `registry:2`'s htpasswd auth is all-or-nothing — every account it admits can also push — so a read-only registry account cannot be made with it. nginx in front of the same storage can: `auth_basic` over two accounts plus `limit_except GET HEAD { auth_basic_user_file <writers only>; }`, with `client_max_body_size 0` and `proxy_request_buffering off` so blobs stream. Proven locally against a real registry with go-containerregistry, the library the CNB lifecycle uses.
- 2026-09-07: A kind e2e job with a component disabled (`--set cert-manager.enabled=false`) turns every path that needs it into dead code there; its green runs said nothing about that path. Check what the job disables before trusting its coverage.
- 2026-09-06: `Seal` in `internal/audit` stamps `time.Now()` when the timestamp is zero, so a "deterministic encoding" test that did not pin the instant flaked at millisecond boundaries. Pin timestamps in any test that seals, hashes or fingerprints.
- 2026-09-07: `kubectl get resourceclaim` resolves to Kubernetes 1.34's built-in `resource.k8s.io` ResourceClaim, not Kitchen's CRD. Always write `resourceclaims.kitchen.bermos.dev` in workflows and docs; a loop that swallowed the error with `|| true` hid this for the whole of a fifteen-minute wait.
- 2026-09-07: `cd ui && npm test` does **not** typecheck — vitest transpiles without checking. A required field added to an interface in `ui/src/lib/api.ts` breaks `npm run typecheck` (vue-tsc) alone, and CI's "Build, typecheck and unit tests" is where you find out. Run `npm run typecheck` beside `npm test` whenever an exported type changes.
- 2026-09-07: An envtest that builds an `Environment` struct by hand and passes it to a helper leaves `spec.type` empty, which now means "no class" rather than "production". Anything keyed on `env.Spec.Type` needs the field set in the fixture, not just the name.
- 2026-09-07: A claim's binding reaches a workload by **two** paths, and a change to one proves nothing about the other: the platform's own variables (`serviceBindingEnv`) and a `fromResourceClaim` entry the project wrote, resolved separately in `resolveEnv`'s `case v.FromResourceClaim != nil` arm. That arm reads `claim.Status.SecretName` and applies the *preview mode*, so a per-class or per-environment binding rule has to be repeated there or a preview silently gets production's address. Test both paths.
- 2026-09-07: `resolveEnv` returning `requeue=true` for an unbound claim makes the environment `notReady` and it never applies its Deployment. Any claim whose binding depends on *another team's* declaration must not go down that path — leave the variable out and say so on `ClaimsBound`.
- 2026-09-07: A condition reason written as a bare string falls to `severityError` in the dashboard — `conditionSeverities` (internal/api/conditions.go) is keyed on the operator's *exported* `Reason…` constants, and `TestEveryExportedReasonIsClassified` only sees exported ones. A new benign reason is three edits: export it, classify it, and check the screen is not now red for being polite.
- 2026-09-07: The API test harness's fake client gives a status subresource only to the kinds listed in `WithStatusSubresource` (internal/api/api_test.go). A handler calling `Status().Update` on any other kind gets a bare `<kind> "<name>" not found` that reads exactly like a missing object — the fix is to add the kind to that list, not to hunt the read.
- 2026-09-07: Turning a ConfigMap *directory* mount into `subPath` file mounts makes any `checksum/` annotation over the raw values wrong: the kubelet re-projects a directory into a running container but never a subPath, and chart values go through `tpl`, so hash the rendered ConfigMap (`include (print $.Template.BasePath "/<dir>/configmap.yaml") . | sha256sum`) or the change never reaches the process.
- 2026-09-07: A StatefulSet whose pod 0 cannot start cannot be fixed by `helm upgrade` — OrderedReady waits for pod 0 Ready *before* applying the new template, so the upgrade hangs. Any fix to a pod-template bug that already bricked installations needs an `### Upgrading …` section in `charts/kitchen/README.md` naming the one `kubectl delete pod` step, and a line in the self-update section's "cannot rescue" list.
- 2026-09-07: A `volumeMount` is only ever exercised by a kubelet, so no `helm template` check can catch one that stops the pod starting — a ConfigMap mounted as a *directory* over a path the image also populates crashes on any subPath mount into it and hides the image's files otherwise (#529, `/etc/clickhouse-server/config.d`). Assert the shape with a render check *and* set the value on the kind leg of `Chart install`, where `helm install --wait` is the only thing that proves a pod starts.
- 2026-09-07: A ClickHouse column added to a table's `CREATE` reaches a fresh install and nowhere else — `ensureAddedColumns` (`signalTransitionColumnsAdded` in schema.go) is the upgrade path, and the integration suite recreates tables so it never exercises it. Test it by `ALTER TABLE … DROP COLUMN IF EXISTS` then re-ensuring; a column named in a read and missing from the table is a query that reads perfectly and fails.

- 2026-09-08: `json:"x,omitempty"` on a `time.Time` never omits anything — a struct is not empty — so an absent instant serves `0001-01-01T00:00:00Z` and contradicts whatever the docs say about the field. Use `omitzero` (Go 1.24+), and assert on the raw response body, since a decoded struct cannot tell the two apart.
- 2026-09-08: Overlaying a refreshed sentence onto a stored row means overlaying what the sentence is *about*: `platform.correlated` recomputes `confidence`, `projects` and `correlates` every round, and refreshing the title alone left "4 projects failing together" over a list of two. Enumerate the descriptive fields that travel with the words, and keep the ones that feed the tier or the clock.
- 2026-09-08: A durable row written once at `StateOpen` is a *record of a moment*, and any screen over it shows the value the condition had when it fired — `internal/api/alerts.go` showed a volume at 85% for ten hours. The refreshed answer already exists in the detection loop's in-memory episodes (`signals.Tracker`); overlay it at read time and date it, never rewrite the row. Check every reader of `OpenSignalTransitions` when you do: `/platform/signals` reads the same rows and was left stale (#547).
- 2026-09-07: A ratio whose numerator and denominator come from different sources passes every test that sets both consistently — `store.disk` divided the `kitchen` database's parts by the PVC's nominal capacity and read 8.4% on a volume 89% full, with green tests either side of the threshold. Assert the *mixed* case (small numerator, full disk) or the bug is invisible (#531).
- 2026-09-08: ClickHouse renames a system log table the first time that log is **next written** after its definition changes, not at server startup — `text_log`/`trace_log` within seconds, `query_log` at the first query, `error_log` possibly hours. Any "clean up what the rename orphaned" step must be a sweep on every reconcile; a one-shot recorded in status collects the loud tables and leaves the quiet ones forever.
- 2026-09-08: A CI assertion of the form "no rows at level X" over a ClickHouse system table passes vacuously against an empty table. Select `count()` alongside the filtered count and require both.
- 2026-09-08: envtest runs **no garbage collector and no storage-protection controller**, so `--cascade=orphan` leaves the object with its `orphan` finalizer forever and every PVC keeps `pvc-protection`. A spec that deletes either and a next spec that recreates it under the same name fails with a 409 nobody expects — strip finalizers in `AfterEach` and wait for the object to go, or drive the delete/recreate path over two reconciles as the production code does.
- 2026-09-08: The API server refuses a size change to an **unbound** PVC — "spec is immutable after creation except resources.requests … for bound claims" — so any expansion path needs the claim Bound, in the fixture and in the code's own precondition. A Pending fixture makes the whole feature look broken for the wrong reason.
- 2026-09-08: Before writing "none of these has a TTL out of the box", read the image's own config: `docker run --rm --entrypoint sh <image> -c 'grep -n <ttl> /etc/clickhouse-server/config.xml'`. The pinned ClickHouse already bounds `query_log` and `processors_profile_log` at 30 days and `asynchronous_insert_log` at 3 — shipping the issue's suggested 7 for the last one would have been the chart *loosening* an upstream bound.
- 2026-09-08: A controller method called from one place and asserted nowhere is invisible to the whole suite. Prove the wiring by commenting the call out and watching the new test fail — and drive the test through the reconcile function, not the helper, or the mutation still passes.
- 2026-09-08: A helper that nils `ManagedFields` on a copy kills every later read of the *field manager* off it — `replacementFor` nil-ed it and `applyOwnerOf` then always answered "", so the whole server-side-apply-under-the-original-owner branch was dead code that every test passed. Assert the ownership on the recreated object (`applyOwnerOf(restored)`), not just that the object came back.
- 2026-09-08: A phase judged on `spec.resources.requests` reports a volume finished the moment the *request* moved; the driver's half is `status.capacity`, and a claim in `ControllerResizeFailed` has the request and not the space. Judge "done" on capacity, and carry the PVC's own condition message rather than composing one.
- 2026-09-08: A reconcile that writes status once at the end writes it with the resourceVersion the pass started with, so every value on it must be *recomputable next pass*. A record of an irreversible act (the system-log DROP, #562) is not: persist it where it happens with `Status().Patch(ctx, obj, client.MergeFrom(before))`, which carries no precondition — and the patch response refreshes the object, so the end-of-reconcile Update is not made stale by your own write.
- 2026-09-08: The controller-runtime fake client *does* enforce resourceVersion on `Status().Update` (given `WithStatusSubresource`), so a lost-update defect is reproducible at unit speed with no envtest: put the object in the client, have the fake HTTP store run a hook that bumps an annotation through a second read, then assert on the stored object rather than the one in hand.
- 2026-09-09: A hostname added to one of the *platform's own* HTTPRoutes is read by more than the gateway: `flows.PublishedHosts` treats every route's hostnames as "the platform published this name", and `edge.unrouted-hosts` subtracts that set — so scoping the port-80 redirect to `*.<baseDomain>` (#573) silently covered every abandoned generated URL and muted the signal. Enumerate the readers of `spec.hostnames` (attribution in `hostsFromRoutes`, publication in `PublishedHosts`) before putting a name on a platform route.
- 2026-09-09: An absence assertion passes against the code it is supposed to fail on: `Expect(list).NotTo(ContainElement(x))` holds for the `nil` the reverted code writes, so the one assertion naming the issue did no work. State the whole expected list (`To(Equal([]string{…}))`) whenever "the new thing is not here" is the point — and prove it by reverting the fix and watching it go red.
- 2026-09-09: A kind step that reads back `.spec` of an object the operator just wrote asserts what the envtest already asserts, twelve minutes and one cluster later. What a cluster leg is *for* is the implementation's side of it — on the Cilium leg the shared Gateway is programmed and publishes an address (`hack/install-cilium.sh` installs LB IPAM) even though its HTTPS listener names a wildcard certificate that is never issued, so a `kubectl run` probe pod curling `status.addresses[0].value` with `-H 'Host: …'` is available; the kindnet leg runs no Gateway controller at all.
- 2026-09-08: A parameter named `client` (e.g. `client *clickhouse.Client`) shadows `sigs.k8s.io/controller-runtime/pkg/client` for the whole function — `client.MergeFrom` will not compile until it is renamed. Check for the shadow before reaching for a controller-runtime helper inside such a function.

## Tooling and environment

- 2026-09-09: The main checkout may have **no** `ui/node_modules` at all (it did not on the #574 run), so the "symlink rather than reinstall" shortcut silently leaves a dangling link and `npm run build` fails with `vite: not found`. Check `ls /home/user/Kitchen/ui/node_modules` before symlinking; `npm ci` in the worktree takes about a minute and is the fallback. Remove the `bin` symlink before committing — it shows up as untracked.
- 2026-09-06: Run `make` with `LOCALBIN=<main checkout>/bin` from a worktree, or it downloads envtest, controller-gen and golangci-lint again. Symlink `ui/node_modules` rather than `npm ci`.
- 2026-09-06: Auth service tests need a local Postgres (`pg_ctlcluster 16 main start`; `KITCHEN_AUTH_TEST_DATABASE_URL=postgres://postgres:postgres@127.0.0.1:5432/kitchen_auth_test`). The ClickHouse integration suite needs Docker (`dockerd &`) and `KITCHEN_CLICKHOUSE_URL` against the pinned `clickhouse/clickhouse-server` image; say in the PR body if you could not run it.
- 2026-09-06: The Go build cache fills the disk over a long session; `find ~/.cache/go-build -type f -amin +120 -delete` and `docker system prune -af --volumes` recover it.
- 2026-09-07: `dockerd &` plus a `docker network`, a `registry:2` and a scratch `_test.go` using the repo's own `go-containerregistry` is a two-minute way to prove a registry-side workflow change before pushing it — push, pull and a refused push, each with a different account. Delete the scratch test before committing; a stray `zz*_test.go` is easy to leave behind.
- 2026-09-07: `make lint` catches what `make test` does not: goconst on a string repeated across test assertions (`"dir"`, a release name), gocyclo at 30 on `Reconcile` (extract a helper), unparam on an always-nil return, staticcheck SA4000 on a "is this stable" test that compares one expression to itself (assert the exact expected string instead).
- 2026-09-07: `kind` does **not** come up in this sandbox even with `dockerd &` running — the control plane's sandboxes die on `runc create ... can't get final child's PID from pipe: EOF` (nested runc). Plain `docker run` works, so an image-layer or bind-mount question can still be answered directly (`docker run -v dir:/path` vs `-v file:/path/file` proved #529's hidden `config.d`); anything needing a kubelet is CI's kind jobs, and say so in the PR body.
- 2026-09-07: `internal/attestation/store.go` is the template for any new OCI-referrer mechanism (#498's release artifacts copied it): attach to a `name.Digest`, read the subject descriptor with `remote.Head` rather than assembling it, push the manifest under a `sha256-<hex>.<suffix>` tag as well so a registry without the referrers API still answers, and be idempotent by layer digest. Do not speak the registry API directly.
- 2026-09-07: `internal/api/requests.go` already exists and is about HTTP *request telemetry*. Check `git show HEAD:<path> | wc -l` before creating a file in a package this big — Write overwrites silently, and the only symptom is a wall of "undefined" errors in unrelated files.
- 2026-09-07: `cd ui && npm run typecheck` fails wholesale (`Cannot find name 'useToast'` in twenty files) until `npm run build` has generated the auto-import declarations. Always run `npm run build` first, then typecheck; CI does.
- 2026-09-09: There is no `gh` in this sandbox, but a full CI job log is still greppable without spending it on context: `get_job_logs` with `return_content: false` answers with a signed blob URL that plain `curl` fetches to a file. A 6200-line Cilium leg is then one `grep` away.
- 2026-09-07: `make test` takes ~10 minutes (the 551-spec envtest suite is most of it) and buffers per package, so a log that has not moved for five minutes is normal rather than stuck. Run it to a file with `run_in_background` and wait with one `until grep -q EXIT= <log>` loop; two concurrent `make test` runs clobber each other's output file.

- 2026-09-09: The worktrees' `bin -> <main checkout>/bin` symlink can point at a directory that does not exist, and `make ... LOCALBIN=` then re-downloads everything per worktree. `mkdir -p /home/user/Kitchen/bin` once before the first `make`; and a *symlinked* `ui/node_modules` is not matched by the `ui/node_modules/` gitignore line (trailing slash means directories only), so it shows up as untracked.
- 2026-09-08: A worktree inherited from a killed session may be checked out on somebody else's branch with a large stale index (wt-532 sat on the orchestrator's branch with 61 staged files). `S=$(git stash create) && git tag <name> $S` makes the discard recoverable, then `git checkout --force <your branch>`; check `git worktree list` before trusting `git log`.
- 2026-09-08: `git rebase origin/main` in a worktree here takes two to five minutes with no output — the `post-rewrite` hook runs `hack/regenerate-generated.sh`. It is not hung; run it in the background and check `git log` after.
- 2026-09-07: `goconst` counts literals across a package's test files, so a claim name used in a fourth test file needs a shared const (`testStoreClaim` in `internal/signals`) before `make lint` is run, not after.
- 2026-09-08: A ClickHouse `config.d` question is answerable in five minutes with plain docker: run the pinned image with `-v $PWD/data:/var/lib/clickhouse`, let it create its log tables, `docker rm -f` and re-run with `-v $PWD/file.xml:/etc/clickhouse-server/config.d/file.xml:ro` (chmod 644). `SHOW CREATE TABLE system.text_log` and the startup line `Merging configuration file '...'` answer whether the file was taken; a second file proves merge order is filename order, last value wins.
- 2026-09-08: `engine_full` in `system.tables` carries the TTL, so a shell assertion needs no `SHOW CREATE` parsing; and creating a fixture table inside the `system` database (`CREATE TABLE system.text_log_99 ...`) is allowed, which is how the reclaim integration test runs against the CI store.
- 2026-09-08: `envtest.Environment` + `AddUser(...).KubeConfig()` written to a file, with a bash script driving the real `helm` and `bin/k8s/<ver>/kubectl` against it, answers a Helm question in about seven seconds and is the only way to establish what `helm upgrade` actually submits. Download a specific Helm from `https://get.helm.sh/helm-v<ver>-linux-amd64.tar.gz`; the sandbox's `helm` is 3.16 while `azure/setup-helm@v4` in CI is Helm 4.
- 2026-09-08: **Helm 4 applies server-side** (field manager `helm`, operation `Apply`); Helm 3 three-way merges. Both reject a changed `spec.volumeClaimTemplates`, and under Helm 4 an object recreated by anything else conflicts on that field forever — recreate it under the manager that owned it through an Apply (read `metadata.managedFields`), not with a plain create and not by stripping managedFields (that leaves a `before-first-apply` owner which conflicts just the same).
- 2026-09-08: `lookup` in a chart template answers an empty map under `helm template`, `--dry-run` and a first install, so a helper that falls back to the value is inert in every CI render — which makes it the way to keep an immutable field out of an upgrade's patch. It does need the caller to be able to `get` the kind in the release namespace.
- 2026-09-08: `npx prettier` in `ui/` finds no repo config and reformats to 80 columns; the repo is hand-formatted at ~120. Running it over an existing file turns a 40-line change into a 340-line one — do not.
- 2026-09-08: `internal/controller` already has a `fakeTelemetryStore` (retention_test.go) that fronts an httptest ClickHouse; a second fake with the same name is a redeclaration error, and extending the existing one (one field, one `case`) is both the fix and the better answer. Check for an existing fake in the package before writing one.

## Rebase and merge

- 2026-09-07: After `git rebase origin/main`, build before trusting the tree: `main` had since exported `ConditionReady` and the branch redeclared it. Regenerate generated files after any rebase; the merge driver keeps one side and a stash pop drops deepcopy and the chart CRDs on purpose.
- 2026-09-06: Files that conflict between concurrent branches: `docs/api/claims.md`, `docs/api/environments.md`, `internal/cli/internals_test.go` (both sides add tests; keep both), `.github/workflows/test-e2e.yml` (both add a case to the same job). Expect and resolve, never hand-merge a generated file.
- 2026-09-07: `git rebase -i` is unavailable here, so to fold a late fix into an earlier commit of your own branch, `git reset --soft origin/main` and rebuild the history by staging paths (`git add api/ internal/ …`) — cheaper and safer than a sequence-editor trick, and it keeps a `fix:` about code that never shipped out of the release notes.
- 2026-09-06: `main` refuses merge commits on push (`GH013`). Catch up with `git fetch origin main && git rebase origin/main` and force-push with lease on your own branch only.
- 2026-09-08: `main` can be *behind itself*: #545, a `chore(agents)` checkpoint note, was cut from a stale base and its merge reverted five landed PRs (61 files, 5083 deletions) including the release manifest. Before resolving a rebase conflict against a hunk you thought was already on main, run `git show origin/main:<file> | grep <the thing>` — if it is gone, the conflict is a revert on main, not your branch being behind. File an issue (#548) and say in the PR body which files your resolution restores.

## CI behaviour

- 2026-09-07: Re-running a workflow run reuses the merge snapshot it was created from; after `main` moves, only a new head gives a fresh run. Re-run only for a setup-step rate limit, a Docker Hub 5xx, or a runner lost before any test body ran, and at most once.
- 2026-09-07: `enable_pr_auto_merge` is refused while any check is failing, required or not ("unstable"). Kind jobs take 15–25 minutes; wait with one bounded loop, not three-minute polls.
- 2026-09-07: A background wait is resumed by its completion notification, never issued and read past: an implementer read the checks six minutes into a normal kind run, took it for an hour-long stall, and cancelled three healthy runs. Wait with one foreground bounded loop, then read; never cancel a run you did not prove hung.
- 2026-09-07: `kubectl exec … -- sh -c "printenv X" 2>/dev/null || true` swallows the *exec's* failure as well as the unset variable, so every negative assertion built on it passes against a container nothing reached. Put the `|| true` inside the container (`sh -c "printenv X || true"`) and capture into a variable — `[ -z "$(cmd)" ]` hides a failure from `set -e`, an assignment does not.
- 2026-09-07: "Several workloads on kind" installs the chart with `auth.enabled=false`, and with no identity provider the API answers every request 401 — so **no API route can be exercised in that job**. A kind case that has to drive an API write writes the object the API writes instead (`kubectl patch --subresource=status`), and says so where it does it.
- 2026-09-07: The required checks are: Build/typecheck/unit tests, Chart lint and render, E2E on kind, Image build, Typecheck and integration tests, Chart install on kind (the aggregate over the kind and Cilium legs), golangci-lint, Unit and envtest, Conventional Commits, Several workloads on kind. Two PRs merged with the last one red before it was required; do not assume a merged PR's e2e passed.
- 2026-09-08: A wholesale revert merged from a stale branch passes every required check — nothing in the suite can assert that a file another PR added still exists. Type and diff size are the only signals; a `chore` PR touching 61 files is the tell.

## Design rules that bit
- 2026-09-09: A request row records no upstream — host, path, status, duration, protocol, trace id and nothing about which side answered — so a gateway `404` for a Host with no route is indistinguishable from the application's own (#574). What *is* knowable is which hostnames the platform is routing: `Domain.status.RouteProgrammed`, recomputed by DomainReconciler from the route and the gateway's acceptance of the listener that hostname rides. Exclude by hostname at read time; never infer per row.
- 2026-09-09: `clickhouse.RequestSeries` built its scope by copying `RequestQuery` field by field, so any new filter on that struct would have been silently dropped for the charts alone — the summary and the route table would have honoured it and the series would not. It now copies the embedded struct and overrides the window. Look for this shape before adding a field to a query struct, and drive the new filter through *every* read in one table-driven test.
- 2026-09-08: A `False` condition whose reason is not in `conditionSeverities` is drawn as a fault *and* usually joins a requeue predicate, so "this is a fact, not a fault" has to be implemented in three places at once: an exported `Reason…` constant, a severity in the table, and a requeue that excludes it. A comment saying it is a fact is not the implementation.
- 2026-09-09: Gateway API cannot express "redirect everything except this path prefix". A rule with no `backendRefs` and no response-producing filter answers 500, and there is no pass-through filter, so a carve-out from a redirect-only route can only be made by a *more specific route* out-precedencing it — hostname specificity is weighed before path, so an exact-hostname route beats a wildcard one whatever its paths. Scope the redirect's hostnames instead of trying to subtract a path from it (#573).
- 2026-09-09: Two conditions that each say "waiting" are not evidence of a cycle. `Domain`'s `RouteProgrammed` is purely observational and gates nothing — it read as a deadlock only because its message named a Gateway listener that cannot exist before the certificate does. Before believing a reported cycle, find the write that actually blocks; then fix the message that suggested one.
- 2026-09-09: Changing what a platform route publishes changes prose nobody greps: `charts/kitchen/README.md` states what each TLS mode does to port 80, and it kept describing the removed catch-all after `docs/` had moved. When a behaviour sentence changes, grep the *sentence* ("port 80") across `charts/`, `docs/` and Go comments, not the paths the issue named.
- 2026-09-08: A poll loop that breaks on "the field is non-empty" breaks immediately on the value the field already had. Poll for the *expected* value, not for presence.


- 2026-09-07: The chart's inline test suite is the `run:` steps of the `lint` job in `.github/workflows/helm.yml` (`helm template` + `grep`, or a `python3 <<'CHECK'` heredoc with `yaml`); there is no separate test file under `charts/`. A new chart assertion goes there, next to the checks about the same template, and is worth running against the *old* template once to prove it fails.
- 2026-09-07: `ServiceOffering`'s Go field names differ from their JSON ones on purpose — `Speaks`/`Authorization`/`VisibleTo` exist because `Protocol`, `Auth` and `Visibility` are already the methods that apply the defaults. A new field with a default-applying method (`contract` → `Contracts`) has to take the same dodge, and the CRD keeps the obvious spelling.
- 2026-09-07: A scripted anchor replace in `api/v1alpha1/build_types.go` is unsafe: `Artifact *ArtifactStatus \`json:"artifact,omitempty"\`` appears three times (Build, workload, release status). Assert the match count or anchor by line number before writing.
