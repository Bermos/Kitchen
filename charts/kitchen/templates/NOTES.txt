Kitchen {{ .Chart.AppVersion }} is installed in namespace {{ .Release.Namespace }}.

Watch the operator come up:

  kubectl -n {{ .Release.Namespace }} rollout status deploy/{{ include "kitchen.fullname" . }}-controller-manager

{{ if .Values.kitchen.create -}}
Platform configuration lives in the Kitchen singleton:

  kubectl get kitchen default

  Base domain:   {{ .Values.kitchen.baseDomain }}
  Generated URLs: <slug>.{{ .Values.kitchen.baseDomain }}   (needs wildcard DNS)
  API / webhooks: {{ include "kitchen.apiExternalURL" . }}

Once the shared Gateway is programmed, point *.{{ .Values.kitchen.baseDomain }} at:

  kubectl get kitchen default -o jsonpath='{.status.gatewayAddress}'
{{- if eq .Values.kitchen.tls.mode "acme" }}

TLS mode is "acme": the Gateway's HTTPS listener expects a wildcard certificate
in the secret "kitchen-wildcard-tls" in {{ .Release.Namespace }}. Issue it with cert-manager
(a Certificate for *.{{ .Values.kitchen.baseDomain }}) before serving traffic.
{{- end }}
{{- if .Values.kitchen.ingress.cloudflared.enabled }}

cloudflared is enabled: the operator runs the tunnel from the secret
"{{ .Values.kitchen.ingress.cloudflared.tunnelSecretName }}". Point the tunnel's public hostnames at the Gateway service.
{{- end }}
{{- if not .Values.kitchen.applyOnUpgrade }}

The Kitchen object was created on install only. Later `helm upgrade` runs leave
it alone so UI edits survive; set kitchen.applyOnUpgrade=true to have Helm own it.
{{- end }}
{{- else }}
No Kitchen object was created (kitchen.create=false). The operator idles until
one named "default" exists:

  kubectl apply -f config/samples/kitchen_v1alpha1_kitchen.yaml

{{ if .Values.webhookReceiver.route.enabled -}}
Git providers deliver events to:

  https://{{ include "kitchen.webhookHost" . }}/webhooks/git/<connection>

The git webhook receiver is only reachable in-cluster
(svc/{{ include "kitchen.fullname" . }}-git-webhook). Expose it, or set

{{ if .Values.api.route.enabled -}}
The operator's REST API answers at:

  https://{{ include "kitchen.apiHost" . }}/api/v1/projects

Every endpoint needs a bearer token from the identity provider. Exchange an API
key for one, then call the API with it:

  TOKEN=$(curl -sS -H "x-api-key: $KITCHEN_API_KEY" {{ include "kitchen.authIssuer" . }}/token | jq -r .token)
  curl -sS -H "authorization: Bearer $TOKEN" https://{{ include "kitchen.apiHost" . }}/api/v1/projects
{{- else -}}
The REST API is only reachable in-cluster (svc/{{ include "kitchen.fullname" . }}-api). Expose it,
or set api.route.enabled=true, before pointing a UI or a CLI at it.
{{- end }}

{{ if .Values.auth.enabled -}}
Sign-in for the platform — and for apps that opt in — is served by
{{ include "kitchen.authIssuer" . }}:

  {{ include "kitchen.authIssuer" . }}/.well-known/openid-configuration

{{ if .Values.auth.bootstrap.enabled -}}
Create the first administrator with this one-time link. It stops working as
soon as this installation has an account:

  echo "{{ include "kitchen.authIssuer" . }}/bootstrap?token=$(kubectl -n {{ .Release.Namespace }} get secret {{ include "kitchen.authSecretName" . }} -o jsonpath='{.data.bootstrapToken}' | base64 -d)"
{{ else -}}
Bootstrap is disabled (auth.bootstrap.enabled=false), so no first-run link was
generated. Create the first account another way before anyone can sign in.
{{ end }}
The operator's credential for registering OAuth clients lives in the secret
{{ include "kitchen.authSecretName" . }} under `serviceKey`; accounts and clients live in Postgres
({{ include "kitchen.postgresHost" . }}).
{{- if not .Values.auth.github.clientId }}

No GitHub OAuth app is configured, so email and password is the only way in.
Set auth.github.clientId/clientSecret with the callback URL
{{ include "kitchen.authIssuer" . }}/callback/github to sign in with GitHub.
{{- end }}
{{- if (include "kitchen.previewGateEnabled" .) }}

Preview URLs are gated behind that login. The operator registers an OAuth client
and runs the gate at {{ include "kitchen.previewGateHost" . }} — it appears a reconcile after the
identity provider starts answering, not with the rest of the release:

  kubectl get kitchen default -o jsonpath='{.status.conditions[?(@.type=="PreviewGateReady")].message}'
  kubectl -n {{ .Release.Namespace }} rollout status deploy/kitchen-preview-gate

Point {{ include "kitchen.previewGateHost" . }} at the Gateway as well — the wildcard record covers it.
Projects opt out one at a time with spec.previews.protected=false; a project that
keeps protection while the gate is off gets no preview URL at all.
{{- else }}

The preview gate is off (previewGate.enabled=false): projects that keep
spec.previews.protected get no preview URL at all. Set it to false per project
to serve previews openly.
{{- end }}
{{- else }}
The identity provider is disabled (auth.enabled=false): there is no login for
the UI, and apps cannot claim OAuth clients. The REST API has no issuer to
validate tokens against either, so every one of its endpoints answers 401 until
an identity provider exists. Preview protection needs it too, so projects that
keep spec.previews.protected get no preview URL at all.
{{- end }}

{{ if eq (include "kitchen.logsEnabled" .) "true" -}}
Container logs are collected on every node and shipped into the `logs` table,
which the operator creates and keeps at {{ .Values.kitchen.observability.clickhouse.retentionDays }} days of retention:

  kubectl -n {{ .Release.Namespace }} rollout status ds/{{ include "kitchen.logsFullname" . }}
  kubectl get kitchen default -o jsonpath='{.status.conditions[?(@.type=="TelemetrySchemaReady")].message}'

Then ask for a project's logs, or a build's:

  SELECT timestamp, message FROM logs WHERE project = '<project>' ORDER BY timestamp DESC LIMIT 100
  SELECT timestamp, message FROM logs WHERE build = '<build>' ORDER BY timestamp
{{- else if .Values.logs.enabled }}
No log collector was installed: there is no telemetry store to ship to.
{{- else }}
The log collector is disabled (logs.enabled=false). Nothing ships container or
build logs into ClickHouse.
{{- end }}

Cluster prerequisites Kitchen assumes: Cilium as the CNI with
gatewayAPI.enabled=true, the Gateway API CRDs, and a reachable address for the
Gateway (L2 announcements/BGP, or cloudflared).
